TripPlanner Data Structure Design
================================

This document details the database schema (Local Room DB & Cloud Firestore), sync mechanism, and security/sharing models for the TripPlanner application.

1. Domain Entities & Database Schemas
-------------------------------------

We define the primary database tables/collections below. To support offline-first operation, the Room local database and the cloud Firestore database will share matching field structures, with additional sync metadata tracking columns present in the local database.

### 1.1 Trips Table (`trips`)
Stores metadata about the trip.
*   `id`: TEXT (UUID or Firestore Doc ID, Primary Key)
*   `destination`: TEXT (Not Null)
*   `startDate`: TEXT (ISO-8601 Date: YYYY-MM-DD, Not Null)
*   `endDate`: TEXT (ISO-8601 Date: YYYY-MM-DD, Not Null)
*   `collaborators`: TEXT (JSON object mapping email -> role, e.g. `{"owner@example.com": "CO_OWNER", "friend@example.com": "VIEWER"}`)
*   `createdAt`: INTEGER (Timestamp in milliseconds)
*   `updatedAt`: INTEGER (Timestamp in milliseconds)
*   *Local-only Sync Columns*:
    *   `syncState`: TEXT (Enum: 'SYNCED', 'PENDING_INSERT', 'PENDING_UPDATE', 'PENDING_DELETE')
    *   `lastSyncedAt`: INTEGER (Timestamp)

### 1.2 Events Table (`events`)
Stores scheduled itinerary items.
*   `id`: TEXT (UUID or Firestore Doc ID, Primary Key)
*   `tripId`: TEXT (Foreign Key pointing to `trips.id`, Indexed, Cascade Delete)
*   `title`: TEXT (Not Null)
*   `category`: TEXT (Enum: 'OTHER', 'FLIGHT', 'LODGING', 'RESTAURANT', 'TRANSIT', 'ACTIVITY', 'ATTRACTION', Not Null)
*   `location`: TEXT (Nullable, physical address or coordinates string)
*   `timezone`: TEXT (IANA Timezone ID, e.g., 'Europe/Rome', Not Null)
*   `startDate`: TEXT (ISO-8601 Date: YYYY-MM-DD, Not Null)
*   `startTime`: TEXT (ISO-8601 Time: HH:MM, Nullable)
*   `endDate`: TEXT (ISO-8601 Date: YYYY-MM-DD, Not Null)
*   `endTime`: TEXT (ISO-8601 Time: HH:MM, Nullable)
*   `description`: TEXT (Nullable)
*   `createdAt`: INTEGER
*   `updatedAt`: INTEGER
*   *Local-only Sync Columns*:
    *   `syncState`: TEXT
    *   `lastSyncedAt`: INTEGER

### 1.3 Notes Table (`notes`)
Stores free-text, checklists, or URL references.
*   `id`: TEXT (UUID or Firestore Doc ID, Primary Key)
*   `tripId`: TEXT (Foreign Key pointing to `trips.id`, Indexed)
*   `eventId`: TEXT (Foreign Key pointing to `events.id`, Nullable, Indexed)
*   `title`: TEXT (Not Null)
*   `type`: TEXT (Enum: 'TEXT_BLOCK', 'CHECKLIST', 'WEB_URL', 'GOOGLE_DOC', 'GOOGLE_DRIVE', Not Null)
*   `content`: TEXT (Not Null. Freeform text for TEXT_BLOCK/URLs; JSON array of checkbox items for CHECKLIST: `[{"text":"Pack passport","checked":true}]`)
*   `createdAt`: INTEGER
*   `updatedAt`: INTEGER
*   *Local-only Sync Columns*:
    *   `syncState`: TEXT
    *   `lastSyncedAt`: INTEGER

### 1.4 Reminders Table (`reminders`)
Stores time-sensitive notifications.
*   `id`: TEXT (UUID or Firestore Doc ID, Primary Key)
*   `tripId`: TEXT (Foreign Key pointing to `trips.id`, Indexed)
*   `eventId`: TEXT (Foreign Key pointing to `events.id`, Nullable, Indexed)
*   `text`: TEXT (Not Null)
*   `date`: TEXT (ISO-8601 Date: YYYY-MM-DD, Not Null)
*   `time`: TEXT (ISO-8601 Time: HH:MM, Not Null)
*   `isTriggeredLocal`: INTEGER (Boolean: 0 or 1, tracks if local device notification has fired. Local only, not synced to cloud)
*   `createdAt`: INTEGER
*   `updatedAt`: INTEGER
*   *Local-only Sync Columns*:
    *   `syncState`: TEXT
    *   `lastSyncedAt`: INTEGER

### 1.5 Packing List Templates Table (`packing_templates`)
Stores global templates created by a user, not associated with a specific trip.
*   `id`: TEXT (UUID, Primary Key)
*   `ownerEmail`: TEXT (Not Null, matches user's Google Sign-In email, Indexed)
*   `title`: TEXT (Not Null)
*   `items`: TEXT (JSON array of strings, e.g., `["Passport", "Toothbrush", "Charger"]`)
*   `createdAt`: INTEGER
*   `updatedAt`: INTEGER
*   *Local-only Sync Columns*:
    *   `syncState`: TEXT
    *   `lastSyncedAt`: INTEGER

2. Cloud Database Design (Firebase Firestore)
---------------------------------------------

We will structure Firestore using a nested sub-collection approach. This provides a natural hierarchy, simplifies data scoping, and reduces cost by allowing hierarchical security rules.

### Firestore Collections Structure:
```
/trips/{tripId} (Document)
   ├── destination: "Rome, Italy"
   ├── startDate: "2026-06-01"
   ├── endDate: "2026-06-10"
   ├── collaborators: { "owner@example.com": "CO_OWNER", "friend@example.com": "VIEWER" }
   ├── createdAt: 1780581200000
   ├── updatedAt: 1780581300000
   │
   ├── /events/{eventId} (Sub-collection Document)
   │      ├── title: "Colosseum Tour"
   │      ├── category: "ATTRACTION"
   │      └── ...
   │
   ├── /notes/{noteId} (Sub-collection Document)
   │      ├── title: "Packing Checklist"
   │      └── ...
   │
   └── /reminders/{reminderId} (Sub-collection Document)
          ├── text: "Submit board pass"
          └── ...

/packing_templates/{templateId} (Document)
   ├── ownerEmail: "owner@example.com"
   ├── title: "Hiking Trip Items"
   ├── items: ["Hiking Boots", "Water Filter", "Compass"]
   ├── createdAt: 1780581200000
   └── updatedAt: 1780581200000
```

3. Offline-First Synchronization Engine
---------------------------------------

The local Room DB serves as the **Single Source of Truth** for the UI. The app interacts only with Room, and a background synchronization system reconciles Room with Firestore.

### 3.1 Local Modification States (`syncState`)
*   `SYNCED`: Local and cloud data are aligned. No action needed.
*   `PENDING_INSERT`: Created offline. Needs to be created in Firestore.
*   `PENDING_UPDATE`: Edited offline. Needs to be updated in Firestore.
*   `PENDING_DELETE`: Deleted offline. Remains in local DB with this status (soft-deleted) so the sync engine knows to delete it from Firestore.

### 3.2 Bidirectional Sync Process
Syncing is orchestrated using **Android WorkManager** to ensure execution even if the app process is terminated or backgrounded.

#### A. Upload Flow (Local -> Cloud)
1.  WorkManager fetches all records from Room where `syncState != 'SYNCED'`.
2.  For each record:
    *   **`PENDING_INSERT` / `PENDING_UPDATE`**: Upload the record to Firestore using its `id`.
        *   On success, update local `syncState` to `SYNCED` and set `lastSyncedAt`.
    *   **`PENDING_DELETE`**: Delete the document from Firestore.
        *   On success, delete the record permanently from the local Room database.
3.  If any upload fails (e.g. timeout, auth loss), WorkManager schedules a retry with exponential backoff.

#### B. Download/Pull Flow (Cloud -> Local)
To download changes made by other collaborators:
1.  Query Firestore for all trips where the user's email is present in the `collaborators` keys.
2.  For each Trip document (and its sub-collections `events`, `notes`, `reminders`):
    *   Compare the Cloud `updatedAt` timestamp with the Local `updatedAt` timestamp.
    *   **If Cloud `updatedAt` > Local `updatedAt`**:
        *   If Local `syncState` is `SYNCED`: Overwrite local Room record with Cloud data.
        *   If Local `syncState` is `PENDING_UPDATE`: Resolve conflict.
3.  For templates, query `/packing_templates` where `ownerEmail == currentUserEmail` and sync similarly.

### 3.3 Conflict Resolution Policy (Last-Write-Wins)
When a conflict occurs (Local has pending changes *and* Cloud has a newer version):
1.  **Timestamp Rule**: Compare the exact `updatedAt` timestamps.
2.  If the cloud modification occurred after the local edit, the local edit is overwritten (Cloud Wins).
3.  If the local modification occurred after the cloud update, the local edit is uploaded and overwrites the cloud data (Local Wins).

4. Sharing & Security Rules
---------------------------

Firestore Security Rules enforce that users can only read or write to data they own or have been shared with.

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Helper functions
    function isSignedIn() {
      return request.auth != null;
    }
    
    function getUserEmail() {
      return request.auth.token.email;
    }

    function getTrip(tripId) {
      return get(/databases/$(database)/documents/trips/$(tripId)).data;
    }

    function hasTripAccess(tripData) {
      return isSignedIn() && (getUserEmail() in tripData.collaborators);
    }

    function isCoOwner(tripData) {
      return isSignedIn() && (tripData.collaborators[getUserEmail()] == 'CO_OWNER');
    }

    // Trips Collection Rules
    match /trips/{tripId} {
      allow create: if isSignedIn();
      allow read: if hasTripAccess(resource.data);
      allow update: if isCoOwner(resource.data) && isCoOwner(request.resource.data);
      allow delete: if isCoOwner(resource.data);

      // Sub-collections inherit rights checking the parent Trip document
      match /events/{eventId} {
        allow read: if hasTripAccess(getTrip(tripId));
        allow write: if isCoOwner(getTrip(tripId));
      }

      match /notes/{noteId} {
        allow read: if hasTripAccess(getTrip(tripId));
        allow write: if isCoOwner(getTrip(tripId));
      }

      match /reminders/{reminderId} {
        allow read: if hasTripAccess(getTrip(tripId));
        allow write: if isCoOwner(getTrip(tripId));
      }
    }

    // Packing Templates Collection Rules
    match /packing_templates/{templateId} {
      allow create: if isSignedIn() && request.resource.data.ownerEmail == getUserEmail();
      allow read, update, delete: if isSignedIn() && resource.data.ownerEmail == getUserEmail();
    }
  }
}
```
