Block 2 (Global & Per-Trip Settings: Timezone Defaults, Sync Interval) [CODE COMPLETE, pending
device check]:
- Added `PreferencesRepository` (data/repository/PreferencesRepository.kt) wrapping the existing
  `user_prefs` DataStore with `defaultTimezone` (String?), `syncIntervalMinutes` (Int, default 15),
  `lastSuccessfulSyncAt` (Long?, written starting Block 3) — per datastructure.txt §6. Made
  `UserSessionManager`'s `Context.dataStore` extension `internal` (was `private`) so this new
  repository can share the same DataStore instance/file instead of opening a second, conflicting
  one.
- Added `SyncScheduler` (sync/SyncScheduler.kt) wrapping the periodic `SyncWorker` WorkManager
  enqueue (`schedulePeriodic(intervalMinutes, policy)`, default policy KEEP). `TripPlannerApplication`
  now reads the persisted interval (via Hilt-injected `PreferencesRepository`) on startup and
  schedules with KEEP (preserves an already-running schedule across app restarts, replacing the old
  hardcoded 15-minute request); Settings calls it with `REPLACE` on an explicit user change.
- Renamed the Profile screen/viewmodel to Settings: `ui/profile/{ProfileScreen,ProfileViewModel}.kt`
  deleted, replaced by `ui/settings/{SettingsScreen,SettingsViewModel}.kt` (same Inner Circle /
  Packing Template sections, unchanged), plus a new "Preferences" section (Default timezone row
  opening a search picker; Sync interval as 5/15/30/60-minute chips) matching designmockups/Main.dc.html.
  `MainActivity`'s `Screen.Profile` route -> `Screen.Settings` ("settings"); `HomeScreen`'s
  `onProfileClick` -> `onSettingsClick` (same Person-icon avatar entry point, just relabeled).
- Added a reusable `TimezonePickerDialog` (ui/components/TimezonePickerDialog.kt) — a modal,
  search-filtered list over `ZoneId.getAvailableZoneIds()` — used by both the Settings screen and
  the new per-trip settings dialog below.
- Added a Trip Settings entry point (gear icon in `OpenedTripScreen`'s top bar) opening
  `TripSettingsDialog`, matching designmockups/TripSettings.dc.html: shows the trip's
  `defaultTimezone` override (or "Using global default: X" / "Not set"), a tap-to-open
  `TimezonePickerDialog`, and a "Clear override" action. Writes go through
  `OpenedTripViewModel.setTripDefaultTimezone()` -> `TripRepository.updateTrip()` (existing
  PENDING_UPDATE path).
- Wired timezone precedence into the Add Event form: `OpenedTripViewModel` exposes
  `globalDefaultTimezone` (from `PreferencesRepository`); `OpenedTripScreen` resolves
  `trip.defaultTimezone ?: globalDefaultTimezone ?: "UTC"` and passes it as `AddEventDialog`'s
  initial timezone. `AddEventDialog` gained a Timezone field (tap to open the same
  `TimezonePickerDialog`) — previously the dialog had no timezone field at all and events were
  silently created with the "UTC" repository default.
- `./gradlew assembleRelease` succeeds from a clean baseline through all these changes.
